ArduLab 사용 전 유의사항

Arduino 시리얼 출력 규칙
ArduLab은 한 측정 시점의 데이터를 변수명:값 형식으로 읽습니다. 여러 변수는 쉼표로 구분하고, 한 측정값 묶음은 한 줄로 끝내세요.
temp:23.5,light:450
  • 변수명은 영문자 또는 _ 로 시작하고 영문자, 숫자, _ 만 사용합니다.
  • 한 측정 시점의 변수들은 같은 줄에 출력합니다.
  • 마지막 변수는 Serial.println()으로 출력하여 줄을 끝냅니다.
  • Serial.begin()의 보드레이트와 ArduLab의 보드레이트를 같게 맞춥니다.
  • 측정 데이터와 같은 줄에 설명 문장이나 단위를 함께 출력하지 않습니다.
  • time은 보통 Arduino에서 보내지 않아도 됩니다. ArduLab이 수신 시간을 기준으로 자동 생성합니다.
사진·영상 분석 유의사항
  • 브라우저 호환성: 영상은 MP4(H.264/AVC) 형식을 권장합니다. 같은 .mp4 확장자라도 내부 코덱에 따라 브라우저에서 재생되지 않을 수 있습니다.
  • 영상 크기: 원활한 분석을 위해 1080p 이하, 짧은 실험 영상, 가능하면 100MB 이하를 권장합니다. 고해상도·장시간 영상은 기기 성능에 따라 느려질 수 있습니다.
  • 프레임 분석: 프레임 단위 위치 분석에는 30fps 또는 60fps의 고정 프레임률(CFR) 영상을 권장합니다. 가변 프레임률(VFR) 영상은 프레임 이동과 실제 촬영 시점 사이에 오차가 생길 수 있습니다.
  • 기준 길이: 영상 또는 사진 안에서 실제 길이를 알고 있는 두 점을 지정하고, 실제 길이와 단위(mm/cm/m)를 정확히 입력하세요. 기준 길이의 두 끝점은 설정 후 드래그하여 미세 조정할 수 있습니다.
  • 좌표축: 원점과 +X축 방향을 지정한 뒤 측정하세요. 설정 후 X축·Y축 끝점 핸들을 드래그해 축을 회전할 수 있고, 빨간색 X축 또는 파란색 Y축 선을 드래그하면 좌표축 전체를 평행이동할 수 있습니다. 기준 길이나 좌표축을 바꾸면 기존 측정 좌표도 새 기준에 맞춰 다시 계산됩니다.
  • 측정점: 추적하려는 물체의 같은 위치(예: 공의 중심)를 매 프레임 일관되게 클릭하세요. 대상이 여러 개인 경우 기록 대상을 구분해서 측정하세요.
  • 샘플 영상: 샘플자료의 공 지름은 4.5cm입니다. 공의 지름을 기준 길이로 사용할 경우 공의 양 끝을 가능한 정확하게 지정하세요.
  • 분석 오차: 영상의 원근 왜곡, 카메라 흔들림, 렌즈 왜곡, 모션 블러, 기준 길이와 물체의 거리 차이 등은 측정 오차를 만들 수 있습니다. 가능하면 카메라를 고정하고 운동 평면에 수직으로 촬영하세요.
  • 데이터 확인: 좌표값과 그래프가 예상과 크게 다르면 기준 길이, 원점, 축 방향, FPS 설정과 측정점 위치를 먼저 확인하세요.
※ 브라우저마다 지원하는 영상 코덱이 다를 수 있습니다. 영상이 재생되지 않거나 프레임 이동이 불안정하면 MP4(H.264/AVC, yuv420p, 30/60fps CFR) 형식으로 변환한 뒤 다시 불러오는 것을 권장합니다.
Arduino 코드 예시
Serial.begin(9600); Serial.print("temp:"); Serial.print(temperature); Serial.print(",light:"); Serial.println(lightValue);
바이브코딩용 초기 세팅 프롬프트
나는 Arduino와 ArduLab을 이용해 실험하려고 해. Arduino 코드를 작성하거나 수정할 때 시리얼 데이터는 ArduLab이 읽을 수 있도록 다음 규칙을 반드시 지켜줘. - 출력 형식: 변수명:값 - 변수가 여러 개이면 쉼표로 구분 - 한 번의 측정값은 반드시 한 줄에 함께 출력 - 예: temp:23.5,light:450 - 변수명은 영문자 또는 _로 시작하고 영문자, 숫자, _만 사용 - 설명 문장이나 단위 등 숫자가 아닌 내용을 측정 데이터와 같은 줄에 출력하지 않기 - 마지막 변수는 Serial.println()으로 출력하여 한 측정 데이터를 한 줄로 끝내기 - Serial.begin()의 보드레이트를 알려주기 - 시간 데이터가 특별히 필요한 경우가 아니면 time은 출력하지 않기. ArduLab이 수신 시간을 기준으로 자동 생성함. 앞으로 내가 요청하는 Arduino 실험 코드는 이 규칙을 유지해서 작성해줘.

⚠️ 영상 FPS 안내

FPS가 왜 중요한가요?

FPS(Frame Per Second)는 영상이 1초 동안 몇 개의 프레임으로 구성되어 있는지를 나타냅니다. ArduLab은 프레임 번호와 FPS를 이용해 측정 시각을 계산하므로, FPS가 잘못되면 시간뿐 아니라 시간으로부터 계산하는 속도와 가속도에도 오차가 생길 수 있습니다.

점 사이 시간 = 점 간 프레임 수 ÷ 영상 FPS 예) 30 fps 영상에서 3프레임 간격으로 측정 → 3 ÷ 30 = 0.1000 s
ArduLab의 FPS 자동 감지 유의사항
  • ArduLab은 영상을 불러오면 브라우저에서 재생되는 프레임의 시간 정보를 이용해 FPS를 자동으로 추정합니다.
  • 30 fps, 60 fps와 같은 일반적인 고정 프레임률(CFR) 영상에서는 자동 감지값을 우선 사용할 수 있습니다.
  • 자동 감지값은 영상 파일의 원본 메타데이터를 직접 읽은 값과 항상 동일하다고 보장할 수는 없습니다.
  • 29.97 fps, 59.94 fps 영상이나 가변 프레임률(VFR) 영상, 특수 코덱 영상에서는 감지값을 확인하는 것이 좋습니다.
  • 자동 감지값이 실제 영상 정보와 다르면 FPS 직접 수정 버튼을 눌러 영상의 실제 FPS를 입력하세요.
영상 파일에서 FPS 확인하기
Windows
영상 파일을 마우스 오른쪽 버튼으로 클릭 → 속성 → 자세히 → 비디오 항목의 프레임 속도를 확인합니다.
Mac
영상을 QuickTime Player로 열고 동영상 정보/검사기에서 프레임률 정보를 확인합니다. macOS 버전에 따라 메뉴 이름이나 표시되는 정보가 다를 수 있습니다.
스마트폰
기본 사진·갤러리 앱의 영상 정보에서 FPS가 표시되면 그 값을 확인합니다. 표시되지 않는 경우에는 촬영 당시 카메라 설정의 30 fps / 60 fps 설정을 확인하세요.
실험할 때 권장하는 방법

가능하면 30 fps 또는 60 fps의 고정 프레임률(CFR)로 촬영한 영상을 사용하세요. ArduLab의 자동 감지값과 영상 파일에서 확인한 FPS가 같다면 그대로 분석하면 됩니다. 두 값이 다르거나 확신하기 어렵다면 영상 파일에서 확인한 값을 FPS 직접 수정으로 입력한 뒤 분석하는 것을 권장합니다.
